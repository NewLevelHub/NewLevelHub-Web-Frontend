# NewLevelHub — Web Frontend

Веб-интерфейс платформы управления коворкинг-пространством **NewLevelHub**. Одностраничное приложение (SPA) на базе Vite и React 18, взаимодействующее с бэкендом на Django REST Framework. Поддерживает четыре роли пользователей с разными уровнями доступа и функциональностью.

---

## Технологический стек

| Инструмент | Версия | Назначение |
|---|---|---|
| React | 18.3.1 | UI-библиотека |
| Vite | 6.3.5 | Сборщик и dev-сервер |
| TypeScript | ~6.0 (strict) | Строгая типизация |
| React Router | 7.13.0 | Клиентская маршрутизация |
| TanStack React Query | 5.96.1 | Серверное состояние, кэширование данных |
| Zustand | 5.0.12 | Клиентское состояние (только авторизация) |
| Tailwind CSS | 4.1.12 | Утилитарные стили |
| Axios | 1.14.0 | HTTP-клиент |
| Lucide React | 0.487.0 | Иконки |
| clsx + tailwind-merge | — | Утилита для классов через `cn()` |

> Tailwind CSS подключён через плагин `@tailwindcss/vite` — **не** через PostCSS-плагин.

## Требования

Перед началом работы убедитесь, что на вашей машине установлено следующее:

- **Node.js** — версия **18** или выше (рекомендуется LTS)
- **npm** — версия **9** или выше (поставляется вместе с Node.js)
- Запущенный бэкенд **Django REST Framework** на `http://localhost:8000` для работы API-прокси в режиме разработки

Проверить версии можно командами:

```bash
node --version
npm --version
```

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone <url-репозитория>
cd NewLevelHub-Web-Frontend
```

### 2. Установка зависимостей

```bash
npm install
```

### 3. Настройка переменных окружения

Скопируйте файл-пример и заполните нужные значения:

```bash
cp .env.example .env
```

Откройте `.env` и укажите актуальные значения (подробнее в разделе [Переменные окружения](#переменные-окружения)).

### 4. Запуск в режиме разработки

```bash
npm run dev
```

После запуска приложение будет доступно по адресу `http://localhost:5173`.

Dev-сервер автоматически проксирует запросы к `/api` на `http://localhost:8000` — бэкенд должен быть запущен.

### 5. Сборка для продакшна

```bash
npm run build
```

Собранные файлы появятся в директории `dist/`. Сборка включает минификацию и оптимизацию ресурсов.

### 6. Предпросмотр продакшн-сборки

```bash
npm run start
```

Запускает статический сервер на порту `3000` для предпросмотра собранного приложения (`dist/`).

### 7. Проверка типов TypeScript

```bash
npm run typecheck
```

Запускает компилятор TypeScript в режиме без вывода файлов (`--noEmit`). Выполняйте эту команду перед каждым коммитом.

## Роли пользователей

Платформа поддерживает четыре роли. Навигация, доступ к маршрутам и возможности интерфейса разграничены по ролям.

| Роль | Описание |
|---|---|
| `superadmin` | Полный доступ к платформе. Управление всеми компаниями, зданиями, пользователями. |
| `company_admin` | Управление своей компанией: сотрудники, бронирования, ресурсы, пропуска. |
| `employee` | Стандартный пользователь компании. Бронирование ресурсов, подача заявок. |
| `guest` | Ограниченный доступ. Просмотр и бронирование отдельных ресурсов. Без функций компании. |

Значения ролей определены в `src/shared/config/constants.ts` в константе `USER_ROLES`. Всегда используйте эти константы для проверок — никогда не сравнивайте с сырыми строками.

## Переменные окружения

Все переменные окружения хранятся в файле `.env` в корне проекта. Доступ к ним осуществляется только через `src/shared/config/env.ts` — не обращайтесь к `import.meta.env.*` напрямую в компонентах.

| Переменная | Пример значения | Описание |
|---|---|---|
| `VITE_API_BASE_URL` | `/api/v1` | Базовый путь для всех API-запросов |
| `VITE_APP_NAME` | `NewLevelHub` | Название приложения |

Пример файла `.env`:

```env
VITE_API_BASE_URL=/api/v1
VITE_APP_NAME=NewLevelHub
```

> В режиме разработки все запросы к `/api` автоматически проксируются на `http://localhost:8000` через конфигурацию Vite — изменять `VITE_API_BASE_URL` для этого не нужно.

## Ключевые соглашения для разработчиков

- **Импорты** — всегда использовать алиас `@/` вместо относительных путей вида `../../`
- **API-пути** — только через константу `API` из `@/shared/api/endpoints.ts`, никаких строк вида `'/api/bookings/'`
- **Константы и перечисления** — только из `@/shared/config/constants.ts`
- **Типы** — только из `@/shared/types/index.ts`, без дублирования интерфейсов
- **Классы CSS** — всегда через `cn()` из `@/shared/lib/cn.ts`
- **Серверное состояние** — TanStack React Query (`useQuery`, `useMutation`)
- **Авторизация** — Zustand через хук `useAuth`, не напрямую из стора
- **Лейауты** — задаются на уровне роутера в `router.tsx`, не внутри компонентов страниц
